# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.
Detailed notes on every part of the app and the data builders are in `docs/NOTES.md`; read the relevant section
before changing that part.

## Goals

A Pathfinder 1e character builder (levels 1-20, multiclass and prestige classes), hosted on GitHub Pages and
used on a laptop and a tablet. Python scripts turn Paizo rules data into plain JSON; a static web app builds
characters from it.

- The user is new to coding. Keep the app plain HTML/CSS/JavaScript with ES modules: no framework, no build
  step, no npm dependencies. Explain any new tool before asking them to install it.
- Paizo content only, and only from books whose OGL Section 15 notice is known (see License below).
- House-rule switches implement the official Paizo version of the rule.

## File layout

- `index.html`, `css/style.css`, `js/` — the app. `js/app.js` owns the page (state, `computeView()`, render);
  `js/rules.js`, `feats.js`, `skills.js`, `weapons.js`, `armor.js`, `equipment.js`, `race-options.js`, `archetypes.js`, `crafting.js`,
  `hero-points.js`, `traits.js`, `spell-math.js`, `dice.js` hold the rules as pure functions; `js/tab-*.js`
  draw the tabs.
- `tests.html` + `js/rules.test.js` — the browser test page.
- `data/*.json` — generated rules data (races, classes, archetypes, feats, traits, spells, armor, weapons,
  equipment, magic items). Change the scripts and rebuild; never hand-edit.
- `scripts/` — the builders (`build_*.py`, run all with `build_all.py`), `validate.py`, and the notice files
  `ogl_notices.json` / `d20_feat_notices.json`.
- `LICENSE-OGL.txt` — generated by `build_license.py`; must ship with the data.
- `manifest.webmanifest`, `sw.js`, `icons/` — make the site an installable app that works offline. `sw.js` saves the
  page, `css/style.css`, every code file reachable by imports from `js/app.js`, and the data files in its `PRECACHE`
  list (add a new `data/*.json` there); online it always fetches fresh files first, offline it uses the saved copy.
- `docs/NOTES.md` — detailed notes. `README.md` — the data record schemas and known gaps.

## Run and test

```
python -m http.server 8000     # from the repo root, then open http://localhost:8000/
```

- The page must be served over HTTP (it fetches `data/*.json`); opening `index.html` directly fails.
- Tests: open `http://localhost:8000/tests.html`. There is no command-line runner (Node isn't installed).
- UI behaviour isn't covered by the tests. Check it in headless Edge (`msedge --headless=new --dump-dom` or
  `--screenshot`) with a scratch page that drives the app in an iframe on the same origin; it must clear
  localStorage first.

## Rebuild the data

With the environment variable `PYTHONUTF8=1` set (Windows would otherwise write non-ASCII text wrongly):

```
python scripts/build_all.py C:\Users\jongo\Projects\PSRD-Data C:\Users\jongo\Projects\foundryvtt-pathfinder1
python scripts/validate.py data
```

- Needs Python 3.9+ with `beautifulsoup4` and `pyyaml`.
- Sources on this machine:
  - PSRD-Data books: `C:\Users\jongo\Projects\PSRD-Data`
  - Foundry pf1 clone (books after 2015): `C:\Users\jongo\Projects\foundryvtt-pathfinder1`
  - d20pfsrd page caches: `C:\Users\jongo\Projects\d20pfsrd-{feats,traits,races}`
- Run one builder from `scripts/` with `PSRD` (and `FOUNDRY`) set, passing the output path.
- Before replacing data after a builder change, rebuild to a scratch folder and compare field by field with the
  current data.

## Key rules

- The Guide tab (`#tab-guide` in `index.html`) explains each tab's features in plain words: update it when a feature
  is added or changes.
- Put new rules math in pure functions (`js/rules.js` or the matching module) and add checks to `js/rules.test.js`.
- The app changes by pure functions plus a full re-render: `update()` → `render()`. `load()` must keep characters
  saved by older versions loading, migrating or dropping old fields.
- Hand-entered facts missing from the sources go in override dicts at the top of the builders
  (`MANUAL_NOTICES`, `FEAT_SOURCES`, `PAGES`, `SPEED_OVERRIDES`, …), not in special-case parse logic.
- License: every book the data uses needs its Section 15 notice in `LICENSE-OGL.txt`. A notice counts only if it
  names Paizo Publishing or Paizo Inc; third-party material on d20pfsrd is left out.
- Commit when a piece of work is done; the user pushes with `! git push`. No cache-busting: just remind them to
  reload the tablet.
